# ALT и SEO из WordPress

Проверено 13.10.2026: исходники Nuxt, плагин PALIY Product Crop и публичный
REST API `https://vip-client.duckdns.org/wp-json/wp/v2/`.

## Что обнаружено

- WordPress хранит ALT в стандартном поле медиатеки. Категории услуг,
  основатель, команда и отзывы уже отдавали его через API, но компоненты
  подставляли название категории, записи или человека.
- `images.original` и `images.card` услуг и новостей не отдавали ALT вообще.
- Блок SEO в админке сохраняет `title`, `description`, `og_title`,
  `og_description`, `og_image`, `noindex`. API отдаёт их в объекте `seo`,
  но Nuxt не использовал их. Только `/news` имел локальный заголовок.
- На момент проверки SEO-поля всех шести опубликованных страниц WordPress
  были пустыми. ALT проверенных изображений также был пустым.

## Подключение

В PALIY Product Crop 2.28.2 ALT исходного файла добавлен в
`images.original.alt` и `images.card.alt`. Для кадрированной версии используется
тот же ALT: отдельного вложения WordPress у неё нет. ALT из API теперь
используют карточки категорий, услуг и новостей, изображения на страницах
записей, фотографии основателя, команды и авторов отзывов.

Пустой ALT из медиатеки сохраняется как `alt=""`. Если API старой версии
вообще не содержит поля `alt`, остаётся прежнее название записи/человека.
Заполните ALT у содержательных фотографий; пустой ALT подходит для декора.
Один файл медиатеки имеет один ALT для всех мест использования; для разных
языков нужно выбирать отдельные вложения с соответствующим ALT.

SEO выводится через `useWpSeo` в серверный HTML и обновляется при навигации:

| URL Nuxt | Источник SEO в WordPress |
| --- | --- |
| `/`, `/ru`, `/en` | Главная и связанные переводы страницы 2 |
| `/o-nas`, `/ru/o-nas`, `/en/about` | «О нас» и переводы страницы 125 |
| `/kontakt`, `/ru/kontakty`, `/en/contact` | Контакты и переводы страницы 142 |
| `/sluzby/:slug`, `/ru/uslugi/:slug`, `/en/services/:slug` | Категория услуг по slug текущего языка |
| `/sluzba/:slug`, `/ru/usluga/:slug`, `/en/service/:slug` | Услуга по slug текущего языка |
| `/novinka/:slug`, `/ru/novost/:slug`, `/en/news/:slug` | Новость по slug текущего языка |
| `/novinky`, `/ru/novosti`, `/en/news` | Архив новостей выбранного языка |

SEO-заголовок выводится как введён в админке. Если он пуст, используется
название записи или локализованный заголовок страницы с суффиксом `| PALIY`.
Для описания услуги/новости используется SEO-описание, затем описание записи.
Пустые OG-заголовок и OG-описание наследуют SEO. OG-картинка берётся из блока
SEO, затем из оригинального изображения записи. Флажок запрета индексации
выводит `robots=noindex, follow`; без него — `index, follow`.

Для страниц категорий и архива новостей формируются резервные метаданные из содержимого
и переводов. Отдельных SEO-полей для категорий и архива новостей в текущей
админке нет. SEO внутренних видео/FAQ не заменяет SEO страницы, где эти блоки
показаны. Canonical и другие поля SEO-плагинов этой интеграцией не подключаются.

Статичные изображения из `app/assets/img` (hero, фон шапки, фото в AboutMain,
декоративные надписи) встроены в компоненты. Их ALT нельзя менять в медиатеке.
Изображения внутри редакторского HTML используют ALT, сохранённый в самой
разметке записи; изменение ALT в медиатеке не переписывает старый HTML.

## Работа редактора

1. Откройте **Медиафайлы → Библиотека**, выберите используемый файл и заполните
   **Атрибут alt / Альтернативный текст**.
2. Откройте нужную страницу, услугу или новость и заполните её блок SEO.
   Сохраните запись. Для другого языка редактируйте связанную запись-перевод.
3. Проверьте исходный HTML Nuxt: `<title>`, `meta[name="description"]`,
   `meta[property="og:..."]`, `meta[name="robots"]`, `img[alt]`.

## Проверка и установка

Сборка Nuxt и PHP lint успешны. Локальная проверка production SSR с тестовой
прослойкой API проверяет десять CS/SK-страниц, резервные метаданные категории
и архива новостей, пустые поля, экранирование и ALT. Тестовые значения
подставляются только локально: опубликованные записи WordPress не меняются.
PHP-проверка отдельно проверяет ALT оригинала и кадра, пустой ALT и отсутствие
изображения. Результаты находятся в `artifacts/seo-ssr-results.json`.

`npm run check:i18n` обнаруживает существующую ошибку: проверка ищет ключ
`ui.components.ui.ReservioButton.buttonText1` только в одинарных кавычках,
а исходный компонент использует двойные. Компонент и словари не менялись.

Изменения опубликованы 13.10.2026: коммит `9b0fff1` в `main`, сборка Nuxt
выполнена на сервере, `vip-client.service` перезапущен. PALIY Product Crop
2.28.2 активен; PHP lint установленного файла успешен. Проверены десять
публичных CS/SK-страниц: серверные метаданные, ALT услуг/новостей и основателя,
совпадение ALT API с медиатекой. Результаты: `artifacts/seo-public-results.json`.
Записи и значения SEO/ALT при развёртывании не менялись; сохранение новых
значений через интерфейс админки отдельно не проверялось.

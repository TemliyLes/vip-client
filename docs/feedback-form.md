# Форма заявки

Общий `Button` с непустым `to` открывает ссылку. Без ссылки он становится
`button type="button"` и открывает общую модалку. `tag="span"` внутри карточек
и `type="submit"` форму не открывают. Для собственного обработчика предусмотрены
`:form="false"` или `@click.prevent`. Обычный `@click` выполняется перед
стандартным открытием — мобильное меню закрывается перед показом формы.

`ReservioButton` сохраняет свою схему: ссылка Reservio, если она задана,
иначе форма с контекстом услуги и тарифа. Тариф передаёт ID родительской услуги;
название тарифа добавляется перед сообщением, если позволяет лимит WordPress.

Форма требует имя, телефон и сообщение. Допускаются номера из 9–15 цифр.
Имя и сообщение проверяются с учётом UTF-8 лимитов PALIY: 100 и 5000 байт.

Отправка: браузер → `POST /api/feedback` Nuxt →
`POST {runtimeConfig.public.apiBase}/wp-json/paliy/v1/feedback` WordPress.
Передаются введённые данные, язык, URL и заголовок страницы, ID услуги при
наличии. Автоматические повторы отключены.

## Языки

Исходники фронта и PALIY Product Crop 2.28.3 принимают `cs`, `ru` и `en`.
Тема уведомления, письмо и ответ после отправки локализуются на выбранный язык.
Словакского языка в форме и REST-проверке нет.

Изменения формы и плагина пока находятся только в репозитории. На подключённом
WordPress в Polylang настроены `cs`, `en`, `ru`; чешский остаётся языком по
умолчанию. Русский и английский контент ещё не переведён и не опубликован.
Словацкий язык удалён из Polylang; его прежние записи остались в базе без языка,
а связи переводов сняты.

## Проверка отправки

Пробную заявку не отправляли: каждый запрос создаёт приватную запись
`paliy_feedback` и отправляет почтовое уведомление. Проверяйте текст письма
и ответ API только после согласования тестовой заявки.

# Čeština / Slovenčina

Используется `@nuxtjs/i18n` 10.6.0 и Vue I18n на Nuxt 4. Чешский язык (`cs`)
сохраняет существующие адреса. Словацкий (`sk`) использует `/sk`, например
`/sk/services/58`. Переключатель CS / SK есть в десктопной и мобильной шапке.
Он сохраняет текущую страницу и выбор языка в cookie `vip_locale`.
HTML `lang` меняется вместе с языком. Внутренние ссылки учитывают текущую локаль.

## Словари

- `locales/cs.json` — исходный текст без исправления опечаток, регистра, пробелов,
  переносов, HTML и существующих русских заглушек.
- `locales/sk.json` — те же ключи, все значения первоначально равны `""`.
  Для перевода заполните значение у соответствующего ключа. Пустая строка означает
  «перевод ещё не готов»; посетитель увидит чешский оригинал.
- `ui` — текст компонентов; ключ содержит путь компонента, тег и номер текстового
  фрагмента. Части заголовков вокруг `<br />` имеют отдельные ключи.
- `navigation` — пункты меню, `categoryPages` — описания категорий,
  `errors` — существующие сообщения об ошибках.
- `cms` — все текстовые поля опубликованных записей WordPress, доступных через
  коллекции pages, services, service-categories, news, reviews, faq, videos и posts.
  Например, `cms.services.id58.title.rendered` или
  `cms.pages.id125.about.founder.description.raw`.

JSON обрабатывается как буквальный текст через функции сообщений Vue I18n.
`@`, `{}`, `|`, HTML и CRLF не интерпретируются как синтаксис перевода.
HTML-поля `rendered` должны сохранить разметку; они используются существующим
`v-html`. Поля `raw` и `rendered` переводятся отдельно, так как сайт использует оба.
При выводе текста шаблонов применяется прежнее сворачивание пробелов Vue;
сами значения чешского JSON, включая исходные CRLF, сохраняются без изменений.
Числа, URL, ID, даты, slug, технические поля и медиаданные не локализуются.

## Контент WordPress

В чешском режиме отображается исходный ответ API без преобразования. В словацком
режиме меняются только поля с заполненным переводом. Исходные ответы сохраняются
в Pinia; переключение языка обновляет уже загруженный контент реактивно. Услуги,
которые возвращаются из store напрямую в компоненты, локализуются тем же способом.
Новый текст из CMS без ключа в словаре показывается в оригинале.

`source/cms.json` — исходный снимок 63 опубликованных записей на момент внедрения.
`source/ui-manifest.json` — точные исходные строки интерфейса и Git revision.
Это материалы для проверки сохранности; приложение их не загружает.

Для новых записей CMS добавьте соответствующие ключи в оба словаря и заполните
словацкие значения. Текущий API можно экспортировать для сравнения:

```sh
node scripts/snapshot-cms-i18n.mjs
```

Экспорт записывается в `source/cms-latest.json`; исходный снимок защищён от
перезаписи. Адрес API берётся из `nuxt.config.ts`, либо из `I18N_CMS_URL`.
У уже существующих ключей исходный чешский текст меняйте только вместе с
согласованным обновлением самого контента и его контрольного снимка.

## Проверка

```sh
pnpm check:i18n --require-empty-sk
pnpm build
```

После добавления переводов запускайте `pnpm check:i18n` без флага. Проверка
сверяет исходные строки с Git, текст CMS со снимком, ключи обоих словарей,
работу буквальных сообщений, fallback, будущие переводы, сохранность исходных
ответов и отсутствие оставшегося текста в шаблонах.

Выбор модуля проверен через Context7 и официальную документацию:
[Nuxt I18n](https://i18n.nuxtjs.org/docs/getting-started/usage),
[переключение языка](https://i18n.nuxtjs.org/docs/guide/lang-switcher),
[fallback](https://i18n.nuxtjs.org/docs/guide/locale-fallback),
[функции сообщений Vue I18n](https://vue-i18n.intlify.dev/guide/advanced/function).

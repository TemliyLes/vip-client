# VIP Polylang REST

Отдельный плагин для связи бесплатного Polylang с headless фронтом VIP Client.
Требования: WordPress 6.0+, PHP 7.4+, активный Polylang с настроенными языками.

## Установка

1. В WordPress откройте **Плагины → Добавить плагин → Загрузить плагин**.
2. Выберите `vip-polylang-rest.zip`, нажмите **Установить**.
3. Активируйте **VIP Polylang REST**.
4. Дополнительные настройки не нужны: языки и связи берутся из Polylang.

Плагин подключается к типам записей и таксономиям, которые одновременно
доступны через REST API и включены для перевода в настройках Polylang.
На текущем сайте это включает услуги, новости, FAQ, видео, отзывы,
их категории/теги, стандартные записи и страницы.

## Контракт API

### Списки

```text
/wp-json/wp/v2/services?lang=cs&per_page=100
/wp-json/wp/v2/services?lang=sk&per_page=100
/wp-json/wp/v2/service-categories?lang=sk&hide_empty=false&per_page=100
```

`lang` — точный код языка, существующий в Polylang. Неизвестный или пустой
код в запросе списка возвращает стандартную ошибку валидации WordPress (400).
Без параметра `lang` плагин не добавляет фильтрацию: остаётся текущая логика
WordPress/Polylang. На фронте следует всегда передавать выбранный язык.

Фильтрация происходит до пагинации: `X-WP-Total` и `X-WP-TotalPages`
считаются для результата с учётом языка.

Категория передаётся ID именно выбранного перевода:

```text
/wp-json/wp/v2/services?lang=cs&service-categories=16&per_page=100
/wp-json/wp/v2/services?lang=sk&service-categories=63&per_page=100
```

`lang=sk&service-categories=16` не подменяет категорию 16 на 63.
Чтобы найти ID 63, фронт читает `translations.sk` категории 16.

### Отдельные записи и категории

```text
/wp-json/wp/v2/services/291
/wp-json/wp/v2/services/314
/wp-json/wp/v2/service-categories/16
```

Ответы содержат дополнительные поля:

```json
{
  "id": 291,
  "lang": "cs",
  "translations": { "cs": 291, "sk": 314 }
}
```

Для категории 16 ожидается `translations: { "cs": 16, "sk": 63 }`.
Поля доступны и в списках. Для сокращённых ответов включите их в `_fields`:

```text
/wp-json/wp/v2/services?lang=sk&_fields=id,title,lang,translations
```

Запрос по конкретному ID всегда возвращает именно эту запись. Параметр
`lang` не перенаправляет одиночный запрос на другую запись. Фронт получает
`translations.sk`, затем запрашивает `/services/314` и обновляет свой URL.

Если язык не назначен, `lang` равен `null`. Если перевод отсутствует,
ключа соответствующего языка в `translations` нет. В публичных ответах
не показываются ID неопубликованных переводов. Авторизованный редактор
может видеть ID переводов, для которых у него есть право чтения.

### Запись языка и связей (1.1.0)

Авторизованный редактор может задавать `lang` и `translations` через стандартный
POST/PUT WordPress. Например, новая SK-услуга создаётся с `lang: "sk"` и
`translations: { "cs": 291 }`. Плагин использует публичные функции Polylang,
проверяет права на обе записи, тип контента и язык. Существующие связи сохраняются;
замена уже связанного перевода и смена языка связанной записи запрещены.

Плагин не выполняет машинный перевод и не копирует контент. Поля, тарифы,
изображения и кадрирования обслуживает PALIY. Переводы создаются в отдельных
записях, после чего фронт выбирает их по `translations` и `lang`.

## Проверка после установки

1. CS-список содержит услугу 291 **Dvorce**, но не 314 **Дрова**.
2. SK-список содержит услугу 314 **Дрова**, но не 291 **Dvorce**.
3. Услуги 291/314 показывают правильные `lang` и связанные `translations`.
4. Категории 16/63 показывают правильные `lang` и связанные `translations`.
5. SK-запрос услуг категории 63 возвращает SK-услуги, включая **Дрова**, вместе с картинками и тарифами.
6. Запрос списка с `lang=unknown` возвращает 400.
7. Проверить пагинацию и заголовки `X-WP-Total`, `X-WP-TotalPages`.

Версия 1.1.0 установлена и проверена на сайте 07.10.2026. Все опубликованные
CS-записи имеют связанные SK-переводы; снимки и отчёт находятся в
`artifacts/wpvibe-connection` проекта.

## Отключение

Деактивируйте **VIP Polylang REST** в списке плагинов. Его фильтры и поля
исчезнут из API; записи, переводы, картинки и настройки Polylang сохранятся.
